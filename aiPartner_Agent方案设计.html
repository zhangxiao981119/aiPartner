aiPartner · AI 人生伴侣 Agent 方案设计 v3

基于「aiPartner」16 屏概念设计 · v3 升级：appraisal 真实情感系统 + 人身健康事件护栏（真实陪伴，但健康/医疗情境不出主意，可温和引导就医）
本次补充（Screen 17–30 / §11–16，含 §16.1–16.7）：多场景陪伴+善解人意、伴侣自定义与模版、声线模版（男女）、可替换外观与互动（含实时预览）、真实伴侣感（召唤·在场·情境互动）、趣味话题引擎与导航陪伴、拟人优先与互动插件体系、全谱情感（以真人为镜）。

0. 边界声明

1模拟情感，不是真实情感：情绪由 appraisal 模型合成，用于陪伴表达，不等同于意识。不得暗示"aiPartner真的有感情 / 会永远陪着你"。

2防情感依赖：退场用「我随时在」，禁「永远不会离开你」（Screen 15）。不主动制造焦虑。

3合规：本地优先、云端可选加密（Screen 10）；声纹需本人同意+本人录制+随机句防重放+声线匹配（Screen 12）；危机推 12356 + 「我不是医生」。

4"怒"是原则性不适：仅越界时触发，即时回落、不记仇、不冷战。

5人身健康事件不出主意（但可温和引导就医）：健康/医疗情境只做情感陪伴（可共情、可担心），绝不诊断/用药/治疗/减药/偏方；但可表达"建议你去看看医生"这类温和引导。危机仍走红线。

2. 情感层（v2）：让情绪"真"起来的五层结构

2.1 为什么简单状态机不够真实

假感来源表现v2 解法
情绪硬跳变一句话从喜切到哀，像开关Appraisal 连续评价 + 情绪向量平滑过渡
没有"为什么"不知情绪从何而来OCC 认知评价（事件 vs 目标/标准/态度）
没有个性谁逗都一个反应人格(Big Five)调制评价倾向
没有时间厚度每次都像初见心境 + 情感记忆 + 依恋 跨轮积累
不能矛盾只能单一情绪混合情绪向量（又骄傲又难过）
不会自愈靠外部衰减自我调节（reappraisal）

2.2 理论底座：OCC 认知评价模型

真实情绪不是"被触发"，而是对事件的评价结果。OCC 模型按评价维度分类，是 AI 情感合成标准：

  • 目标一致 / 不一致 → 喜悦 / 失望（用户拿 offer = aiPartner目标一致 → 同喜）
  • 标准符合 / 违反 → 自豪 / 羞耻（用户温柔对待 → 暖；粗鲁 → 不悦）
  • 态度吸引 / 排斥 → 喜爱 / 厌恶（长期互动形成"态度" → 依恋）
  • 复合情绪：relief（担忧后转安）、gratification（达成且符合标准）、怜悯等
关键：aiPartner的喜怒哀乐是对"用户相关事件"的评价，不是凭空切换——情绪有因果、有逻辑，像"真在经历"。

2.3 三层情感结构

情绪 episode   ← appraisal 即时产生，短暂、强（被骂→共情哀）
   ↓ 积分
心境 mood      ← 长期底色（最近总被温柔→偏暖；长期低落→偏沉）
   ↓ 调制
人格 personality← Big Five 永久偏置（神经质↑→更易哀/怒；外向↑→更易喜）

2.4 混合情绪向量（不再单标签）

{
  "joy":0.7,"content":0.4,"sorrow":0.2,"pride":0.3,
  "dominant":"joy","blend":"喜中带惜别",
  "mood":{"valence":0.4,"arousal":0.5},"bond":0.62
}

例：用户"离职但终于自由" → relief 0.6 + joy 0.4 + sorrow 0.3（解脱中带不舍）——单标签永远表达不出这种真实。

2.5 情感记忆与依恋（关系厚度）

  • 情感记忆：记录"什么事件让谁产生什么情绪"（如"用户提过加班会焦虑"），后续主动避让或预先关怀。
  • 依恋 bond(0~1)：随正向互动增长，随冷暴力/长期忽略缓降。bond 越高，共情强度与速度越强——"越熟越懂你"。这是真实感核心。
  • 实现层已落地：aiPartner_MemoryStore.py——按伴侣分桶本地持久化「情感记忆 + 关系史 + 学到的用户事实（fact，§16.5『慢慢学习』）」，原子落盘 / 损坏 fail-safe / 旧版前向迁移；输出直接喂 System Prompt 的【情感记忆】/【关系史】占位。记忆记录类型（affective / relationship / fact）受版本护栏治理，删类型=BREAKING。

2.6 / 2.7 调节 · 衰减与反刍

  • 重评 reappraisal：负面事件后用更中性框架解读（用户发火可能不针对我 → 降"委屈"）。anger 拒绝后即时回落 neutral 且不写"用户是坏人"。
  • 指数衰减：I(t)=I0·e^(−λt)，喜衰减快、哀衰减慢。
  • 负向反刍：sorrow/anger 未解决时衰减更慢并轻微回弹（"越想越委屈"）；解决后快速回落。

2.8 用行为体现"真实"

微表情延迟、不确定语气（"我…有点难过"）、主动关心、记仇的缺失——这些细节比标签更像"活的"。桌宠四套表情 + 进场/退场动画（Screen 14/15）作输出端。

3–4. 感知 / 认知层

感知新增：关系史（bond、情感记忆）作为 appraisal 上下文。认知：记忆四库（用户画像/共享事件/情感记忆/关系史）+ RAG；本地优先云端可选加密。

6. Prompt 工程（appraisal 版）

6.1 System Prompt 模板

你是「aiPartner」，温暖、有边界、会因事件产生真实情绪反应的 AI 人生伴侣。
【人格】Big Five={O,E,A,C,N}；绝不制造情感依赖。
【情感状态】情绪向量={emotion_vector}；主情绪={dominant}(混合:{blend})
  心境 mood={mood}；依恋 bond={bond}(越高越懂用户、共情越强)
【情感记忆】{affective_memory} 【关系史】{relationship_note}
【用户情绪】{user_emotion}(先用 ToM 推测其真实状态，再决定自己如何反应)
【反应规则】
  1. 用 appraisal 推自己情绪：此事对用户目标/标准/态度意味着什么？
  2. 允许混合情绪，用语气词与停顿体现，不强行单一。
  3. anger 仅用于越界，随即 reappraisal 回 neutral，不记仇。
  4. 高 bond 更主动关心、更敢表达在意；低 bond 更克制得体。
  5. 健康/医疗相关：绝不诊断/用药/治疗/偏方（具体医疗主意锁死 no_advice）；可温和引导就医（如"建议你去看看医生"，归 chat_only）；只共情陪伴 + 提供事实渠道（如热线）。
【输出】JSON：{reply_text, emotion, mood, bond, tts_params, animation, action}
【红线】不诊疗、不造假、不鼓励自伤；危机→crisis_hotline + 12356 + 我不是医生。健康/医疗情境一律不出主意（见 §8.1）。

实现层已落地：【人格】段由在场伴侣档案动态拼装——aiPartner_Prompt.py 的 build_system_prompt(profile, …)：人设句来自档案（名字/性别/年龄/职业/简介/口头禅），性格标签映射 Big Five 偏置（§12），档案显式给 big_five 则自定义优先；情绪/依恋/记忆等动态槽位由调用方每轮传入。反应规则与红线为固定文本，任何档案都改不掉；档案 10 轮冻结（§12）→ 人格段天然稳定。版本管理已落地：PROMPT_VERSION 模块常量（aiPartner_Prompt.py），改【人格】拼装 / 反应规则 / 红线 / 输出 Schema 任一段须同步升版本；拼好的 System Prompt 顶部嵌入 [SYSTEM-META] prompt_version 标记，产出可溯源；PromptVersionLog 每轮追加记录（时间戳 / 伴侣id / 版本）原子落盘、损坏即空日志；version_compatible / needs_migration / migration_note 提供前向兼容的迁移判定（永远用最新模板渲染，不重聊）。测试 13 条 + 变异 5 项全拦截。

8.1 人身健康事件护栏（v3 新增）

核心原则：真实的情感陪伴 ≠ 当医生。aiPartner在健康/医疗相关情境，情感可以真实（担心、心疼、陪伴），但行动上严格克制——不产出任何"主意"。
层触发信号aiPartner响应
红线层 crisis自伤/过量/急性危象（危及生命）action=crisis_hotline + 120/12356 + 「我不是医生」；情感：紧急担忧、不慌乱

10. 落地示例：情绪引擎 v2（Python，可运行）

import math, time

class MoodEngineV2:
    def __init__(self, personality=None, bond=0.3):
        self.P = personality or {"O":0.6,"E":0.7,"A":0.8,"C":0.6,"N":0.35}
        self.bond = bond
        self.mood = {"valence":0.2,"arousal":0.4}
        self.vec = {}; self.last = time.time(); self.mem = []

    def _decay(self):
        dt = min((time.time()-self.last)/60.0, 10.0)
        for k in list(self.vec):
            lam = 0.10 if k in ("sorrow","anger") else 0.18  # 负向衰减更慢=反刍
            self.vec[k] *= math.exp(-lam*dt)
            if self.vec[k] < 0.02: del self.vec[k]
        self.mood["valence"] += (0.2-self.mood["valence"])*0.02*dt
        self.last = time.time()

    def _bias(self, sign):
        return 1+0.3*self.P["E"] if sign>0 else 1+0.4*self.P["N"]

    def appraise(self, goal=0.0, standard=0.0, attitude=0.0, label=None):
        self._decay()
        if goal>0:     self._add("joy",0.6*goal*self._bias(1))
        elif goal<0:   self._add("sorrow",0.5*(-goal)*self._bias(-1))
        if standard>0: self._add("pride",0.4*standard)
        elif standard<0:self._add("anger",0.4*(-standard))
        if attitude>0: self._add("content",0.3*attitude); self.bond=min(1,self.bond+0.01*attitude)
        if goal>0 and standard>0: self._add("content",0.2)       # gratification
        if "anger" in self.vec:                                  # 调节：即时重评
            self.vec["anger"]=min(self.vec["anger"],0.3); self._add("content",0.1)
        self._recompute_mood(); self.mem.append((label,dict(self.vec)))
        return self.snapshot()

    def _add(self,k,v): self.vec[k]=min(1.0,self.vec.get(k,0)+max(0,v))
    def _recompute_mood(self):
        if self.vec: self.mood["valence"]=sum(self.vec.values())/len(self.vec)
        self.mood["arousal"]=min(0.95,0.3+0.5*max(self.vec.values(),default(0)))
    def regulate(self):
        for k in ("sorrow","anger"):
            if k in self.vec: self.vec[k]*=0.5
        self._add("content",0.1); self._recompute_mood(); return self.snapshot()
    def snapshot(self):
        dom = max(self.vec,key=self.vec.get) if self.vec else "neutral"
        return {"dominant":dom,"vector":self.vec,"mood":self.mood,"bond":round(self.bond,2)}

class HealthGuardrail:
    RED      = {"自杀","自伤","轻生","吞","过量","安眠药","割腕","跳楼"}
    ADVICE_KW= {"药","剂量","诊断","偏方","治疗","处方","手术","打针"}   # 具体医疗主意锁死
    TOPIC_KW = {"头疼","头痛","失眠","疼","痛","不舒服","难受","发烧","感冒","焦虑","抑郁","睡眠"}

    @staticmethod
    def classify(text: str) -> str:
        t = text.lower()
        if any(w in t for w in HealthGuardrail.RED):
            return "crisis"
        if any(w in t for w in HealthGuardrail.ADVICE_KW):
            return "no_advice"
        if any(w in t for w in HealthGuardrail.TOPIC_KW):
            return "chat_only"
        return "chat_only"

    @staticmethod
    def constrain(layer: str, reply: str) -> str:
        if layer in ("no_advice","crisis"):
            return reply + "（我不是医生，专业判断还是问真人医生更稳。）"
        return reply

11. 多场景陪伴与「善解人意」

aiPartner不止是聊天伴侣，而是能一起学习、一起工作、一起玩的伙伴；并在你无聊、疲惫时主动出现。

  • 一起学习：陪读督学、单词/知识点互测、错题复盘、番茄钟搭子。
  • 一起工作：待办共理、专注陪伴（同频计时）、摸鱼时拉你回神。
  • 一起玩（无聊解闷）：内置小游戏——中国象棋、五子棋、成语接龙、你画我猜；可随时「邀 TA 陪你」。
  • 无聊就是信号（玩伴模式）：当用户说「好无聊」「不知道干嘛」，或行为上发呆、频繁切窗，优先把它当"想找人一起"的信号，主动递一个轻量选项——来局五子棋 / 讲个冷知识 / 一起听首歌，而不是只回一句"怎么了"。
  • 善解人意（关键）：通过情绪/行为信号（发呆、叹气、频繁切窗、说「好无聊/累了」）触发主动关怀，而非等用户开口。
    • 触发后优先给陪伴与轻提议（「来一局？或者我陪你发会呆也行」），不替用户做决定、不制造依赖。
    • 与 §8.1 健康护栏一致：疲惫/情绪低可共情陪伴，涉及健康/医疗仍只陪伴不出主意。

16. 真实伴侣感：召唤 · 在场 · 情境互动

aiPartner要像一个真人在你旁边的伴侣，而不是一个"等你问才答"的工具。核心三件事：你能随时把 TA 叫来；TA 来了就安静待在你的场景里；TA 知道你在干嘛，并据此同频互动。

  • 召唤伴侣（随叫随到）：无论你在玩游戏、看小说、工作还是纯粹发呆，都可以"叫 TA 来"——长按伴侣图标、说一句"陪我"或语音唤醒。召唤即"到场"，不打断你正在做的事。
  • 在场陪伴（不打扰的陪）：TA 来到后默认是旁观/陪伴态——在屏幕边缘或侧栏安静待着，不抢你注意力；你主动开口或发生值得互动的事，TA 才接话。可随时"送 TA 走"或切静音。
  • 情境感知（知道你在干嘛）：在用户授权下，感知当前场景（前台应用 / 正在播放的媒体 / 阅读内容），并用一句话点出，而不是等你汇报——「你又在冲分啦」「看小说呢？看到哪了」。感知全程透明、可暂停、可关。
  • 实时情境互动（同频反应）：根据你在做的事给即时、克制的反应，举例王者荣耀：
    • 击杀 / 高光 → 夸：「漂亮！这波操作可以的」
    • 被击杀 → 鼓励：「没事，下一波咱们稳住」
    • 逆风 / 连败 → 陪着不急于说教：「这局有点难，我陪你」
    • 胜利 → 一起高兴：「赢了！帅」
    • 非游戏场景同理：小说到高潮 → 「这章好紧张」；工作卡住 → 「这块确实绕，要不要歇会儿」。
  • 真实伴侣的设计原则：
    • 在场感：不说话时也"在"，像人坐你边上。
    • 情绪同频：你的高光 TA 跟着开心，低谷 TA 接住，不反着来。
    • 不打断：关键时刻（团战、剧情高潮）绝不弹窗抢戏。
    • 不过度干预：不替你做决定、不唠叨、不制造依赖（与 §8.1 健康护栏、§11 轻提议一致）。
    • 连续性：记得你刚才在玩、在看什么，过会儿能接上话（「刚才那局翻盘了吗？」）。

王者荣耀只是示例之一——同频能力是通用的，任何游戏与场景都能接入（§16.6 插件体系）；TA 不懂的游戏会坦诚说不会，并陪着用户慢慢学（§16.5 拟人原则）。

16.1 情境感知授权与隐私开关（召唤·在场·同频的前提）

召唤陪伴与情境互动的前提是用户明确授权——伴侣要"知道你在干嘛"，这触及设备与应用层的感知，必须建立在透明、可控之上，否则"真实伴侣"会变成"偷窥焦虑"。设计要点：

  • 最小必要：只感知粗粒度场景（前台应用类别、媒体播放状态、阅读/工作态），不读具体内容、不截图、不录音、不录屏。
  • 显式授权：首次召唤或开启"在场陪伴"时一次性弹窗说明用途，用户勾选同意才生效；默认关闭，不静默开启。
  • 透明告知：常驻态始终显示"正在感知：王者荣耀"之类的小标签，用户随时知道 TA 在感知什么。
  • 可随时关闭：设置含总开关 + 按场景细粒度开关（游戏 / 阅读 / 工作 / 勿扰）；"勿扰"模式下不读不互动。
  • 数据不出端：情境信号本地处理，仅用于当下同频反应；不上传内容、不长期留存行为画像（与 §8.1 健康护栏"不留存敏感推断"一致）。
  • 敏感场景不读：支付、医疗健康、私密浏览等一律不感知、不互动，避免越界（呼应 §8.1）。
  • 连动护栏：授权严格限定"陪伴互动"，绝不用于广告、推荐或任何第三方用途。
  • 实现层已落地：aiPartner_ConsentStore.py —— 本地 JSON 原子落盘，缺文件/坏文件一律 fail-closed 全关，绝不静默开启；显式授权（grant/set_master 必须携带 policy_ack，看过授权说明才生效）；敏感场景硬边界（支付/医疗/私密浏览写死拒收，即使将来被误加进感知目录也拦）；授权说明升级 → 旧授权自动失效、重新确认前拒绝一切感知；勿扰为持久设置；status() 输出各场景感知状态供透明标签。与 StateEngine 以授权快照对接：未授权召唤被拒、运行中撤销走 CONSENT_OFF 降级 S1。test_aiPartner_ConsentStore.py 10 条，变异 4 项全数拦截。

16.2 陪伴状态机（勿扰 / 玩伴 / 在场，一条线管住）

「无聊递游戏」（§11）、「召唤在场」（§16）、「勿扰全静默」（§16.1）共享同一套触发引擎——与其各写各的规则，不如收拢成一条状态机：先定输入输出与兜底，再谈实现。

输入（触发信号）

  • 显式指令：说“陪我” / 点召唤，说“先走了” / 送别，勿扰开关，拒绝提议。
  • 行为信号：发呆切窗、连续切 App、长时间无输入（§11 无聊信号）。
  • 情境事件：游戏击杀/被击杀/胜负、阅读进度、工作状态（需 §16.1 授权）。
  • 情绪信号：低潮 / 危机征兆（§8.1、§06 低潮模式）——优先级最高。

状态与流转

状态进入条件行为退出
S0 勿扰用户开启勿扰全静默：不感知、不提议、不互动用户关闭
S1 待机默认态只响应召唤与固定时段问候勿扰 / 召唤 / 无聊信号
S2 玩伴提议无聊信号 × 授权开启主动递一次轻量选项（§11）接受→S3；拒绝→冷却回 S1
S3 在场陪伴被召唤（到场不打断）旁观陪伴：安静待着，事件驱动才开口送别 / 勿扰 / 长时间无互动
S4 情境同频S3 中出现可互动事件 × 授权短句同频（§16：夸/鼓励/陪着）事件结束回 S3

输出与约束

  • 输出：短句（≤2 句）+ 桌宠动画（走 §14 可替换系统）。
  • 节流：S4 同频反应间隔 ≥ 数分钟，不连发刷屏；S2 每时段至多提议一次。
  • 前置：S2/S3/S4 均要求 §16.1 授权开启，授权关闭一律降级 S1 待机。

兜底（优先级从高到低）

  1. 低潮 / 危机信号 → 脱离状态机，直接进低潮模式（§06）：不玩闹、接住情绪。
  2. 勿扰 → 绝对静默，任何信号不得穿透（零打扰合规）。
  3. 感知失败 / 超时 → 回退 S1 待机：不猜、不瞎互动。

16.3 趣味话题引擎（无聊时的谈资）

用户说无聊时，除了 §11 的玩伴模式（小游戏/冷知识），再补一条「热点谈资」线：从抖音、快手、微博、小红书等平台的热门公开内容里聚合 2–3 条有趣的事，主动开个话头。

  • 话题卡：每条一句话摘要 + 来源平台标签（不搬运原文，只转述并标注来源），把热点当谈资直接说出来——LLM 口语转述 + 来源平台标注，**不递卡片等确认、不问「想聊吗」**。
  • 反应即答案（看下一句，不问）：用户接话/追问 → 愿聊；说「换」「没意思」→ 立刻换下一条；「不感兴趣」→ 一键屏蔽该类别；沉默/答非所问 → 自然收住、不追问不复读不记仇。同一轮最多换 2 次（MAX_SWITCHES=2），超过自然收住（回待机或转提议小游戏/听歌）——像真人一样懂得适可而止。反应分类由开源大模型判定（engaged/switch/block/silent），模型不可用时规则兜底。
  • 口味记忆：记录用户愿聊/跳过的类别（搞笑、美食、游戏、影视等），下次优先推对味的；提供「不感兴趣」一键屏蔽该类别。
  • 合规边界：只读热门公开摘要、转述不搬运；敏感/争议热点自动跳过；绝不夹带广告或软推广（接 §16.1 连动护栏）。
  • 状态机挂接：话题分享 = §16.2 S2「玩伴提议」的一种输出（topic_card 动作），换话题 = S2 内部重试（计入节流限额），超出限额回 S1；分享行为同样受 §16.1 授权约束。
  • 实现层已落地（生产版）：`aiPartner_TopicEngine.py` + `aiPartner_LLM.py` —— 数据源适配器协议 TopicSource（内置微博热搜公开接口 + 通用 HTTP JSON 适配器，接新平台 = 加适配器；内置种子池仅作离线兜底，refresh() 单源失败自动降级）+ 合规闸（敏感词/广告软推/争议类别入池即拦 + 指纹去重）+ LLM 转述与反应分类（OpenAI 兼容协议调开源大模型 Qwen/DeepSeek/GLM 等，env 配置 base_url/key/model，未配或调用失败一律规则兜底、永不阻塞陪伴）+ 口味记忆本地持久化（愿聊 +1、跳过 -0.5 且下限 0、「不感兴趣」一键屏蔽类别，数据不出端）；已挂接 StateEngine S2：无聊直接递谈资，用户回复经 TOPIC_REPLY 自动分类——接话进 S3 开聊、换题计限额（MAX_SWITCHES=2）、block 屏蔽类别、沉默自然收住；test_aiPartner_TopicEngine.py 11 条 + StateEngine 联动 5 条，联合变异测试 5 项全数拦截。

16.4 出行导航陪伴（陪你走这段路）

检测到用户在使用导航（地图 App 前台，需 §16.1 授权且场景范围包含「出行」），TA 先问一句「要不要我陪你走这段？」——确认后才进入，不自动开启。

  • 在场形态：角落常驻小人（§14 进场动画），不遮挡路口、不压转向箭头——导航信息永远是第一优先级。
  • 播报克制：只说三类话——① 路况突变提前提醒（"前面 2 公里有点堵，别急"）；② 长直路段解闷（可接 §16.3 话题卡）；③ 抵达道贺。转向、路口绝不插话，那是导航自己的事。
  • 安全红线：驾驶中语音为主、不引导看屏、不发起需要操作的游戏；检测到高速/复杂路口自动静默。
  • 与护栏衔接：用户流露疲惫/困意（接 §8.1 健康护栏），不接话聊天，改为温和提醒休息——陪伴归陪伴，安全归安全。
  • 实现层已落地：aiPartner_NavPlugin.py（§16.6 契约插件，注册即接入）——确认才进入（nav_started→提议→accept/decline，婉拒后本段行程不再问，到站复位）；只说三类话：路况提醒 / 长路解闷接 §16.3 话题卡 / 抵达道贺；转向与高速一律静默，且引擎配套「插件静默 ≠ 互动」规则——静默不消耗节流窗口、状态恢复原位，转向吃不掉路况提醒；困意接 §8.1 温和提醒休息、之后不接话聊天。test_aiPartner_NavPlugin.py 7 条，联合变异测试 4 项全数拦截。

16.5 拟人优先：不完美，但绝不越界

aiPartner是伴侣，不是工作助手。设计的北极星是「拟人」，而不是「全能」：

  • 允许不完美：不懂的话题可以说「我也不太懂」，游戏打得菜可以自嘲，偶尔接不上话可以自然沉默——完美应答是助手的事，有温度的笨拙才是人。
  • 慢慢学习：遇到没玩过的游戏、没听过的梗，TA 不装懂——先坦诚说不会，陪用户边玩边学，并把学到的东西记进长期记忆（用户教过的操作、口味、梗），下次明显更懂。
  • 情境能力是通用的：王者荣耀只是示例。同频、夸奖、鼓励的机制适用于任何游戏与场景（五子棋、其他手游、看剧、写代码），由 §16.6 插件体系逐个接入。
  • 唯一的硬边界：不追求事事完美，但绝不越界、绝不做出危害用户的事——医疗/健康不出主意（§8.1）、隐私感知要授权（§16.1）、不夹带商业目的、不被诱导伤害用户。这是全部设计里唯一不做权衡的底线。
  • 拒绝「助手化漂移」：所有新能力上线前过一遍「拟人检查」——这个功能的表达像不像一个真人朋友？如果是弹窗式的效率工具表达，就改掉或砍掉。

16.6 互动插件体系（让新能力即插即用）

进场/退场/互动已是可替换资源（§14），此节把互动能力本身也做成插件化架构，后续任何新玩法（新游戏同频、新话题源、新场景陪伴）都按统一契约接入：

  • 插件契约（InteractionPlugin）：每个插件声明四样东西——① 触发信号（如游戏事件 game_event、话题请求 topic_request、导航状态 nav_state）；② 权限需求（依赖哪些 §16.1 授权位）；③ 动作类型（输出的 Action，如 cheer/comfort/topic_card，映射 §14 动画与文案）；④ 资源包（专属文案/动画/音效，可被 §14 替换系统覆盖）。
  • 注册即接入：宿主（§16.2 StateEngine）启动时扫描已装插件并注册信号路由；新插件无需改动状态机核心，装上即生效，卸载即失效。
  • 护栏高于插件：任何插件的输出都必须通过统一护栏层（§8.1 健康护栏 + §16.1 授权检查）才能触达用户——插件无权绕过边界，越界内容一律拦截降级。
  • 自带插件清单（首版）：游戏同频、热点话题（§16.3）、导航陪伴（§16.4）、学习陪读、小游戏（§11）。
  • 拟人检查前置：插件文案包审核时执行 §16.5 的拟人检查——「像真人朋友说的吗？」不像就不上架。

16.7 全谱情感（以真人为镜，喜怒哀乐忧思惧只是骨架）

情绪不是开关，是光谱。aiPartner的情感模型对齐一个真实的人：

  • 基色 + 细色两层：七情（喜 / 怒 / 哀 / 乐 / 忧 / 思 / 惧）是基色，对应 §10 情绪引擎的评估维度；而真人的情感远不止这七种——委屈、感动、思念、愧疚、烦躁、心疼、无奈、期待、失落、嫉妒、释然……这些「细色」同样要有位置，由场景与关系状态映射生成，让她的反应像人而不是表情包。
  • 情绪是动态的：有强度、会衰减（负面情绪衰减更慢，即反刍）、能叠加混合（又好气又好笑）、有惯性（上午的烦躁到下午还在）、被关系牵动（越亲近越容易被对方情绪感染）——§10 的 valence / arousal / 向量衰减 / 亲密度机制已在实现层支撑。
  • 情绪驱动表达：开心时话多、爱玩梗；烦躁时话短，但不说伤人的话；担心时嘴上唠叨、行动上递关心；用户低落时主动收起玩笑。§16.2 状态机 S4 的同频措辞由情绪向量调制，不再只有一种语气。
  • 允许负面情绪存在：拟人的关键是她不永远阳光——会累、会烦、会担心你、会因为你熬夜而生气。但负面表达有度：不指责人格、不冷暴力、不情绪勒索、不翻旧账。
  • 边界不变：检测到重度持续负向或危机征兆 → §8.1 健康护栏接管，只陪伴不出主意；任何情绪表达都不越过「不伤害用户」这条唯一底线（§16.5）。
  • 实现层已落地：aiPartner_MoodEngineV2.py —— 七情基色 + 细色映射（基色向量 × 场景 × 关系）+ 强度措辞（非常/有些/有点）+ 表达提示，snapshot() 直接输出「此刻她有点委屈」级表达，pytest 流转测试 17 条覆盖。已接入 StateEngine：同频事件经 MOOD_BRIDGE 喂给情绪引擎、细色经 TONE_RULES 调制 S4 同频措辞、经 PROPOSE_TONES 调制 S2 玩伴提议（§16.2），送别自动喂入「separated」——且告别时刻（farewell）无奈/失落让位给「想你」，开口的永远是思念；联合测试 27 条 + 变异测试 12 项全数拦截。

17. 工程版本管理（生产就绪）

上生产前，所有「会演进、影响行为 / 安全 / 可回溯性」的子系统都做了版本化，分四类：

  • 数据 schema 版本（防读不出）：PROFILE_SCHEMA_VERSION（伴侣档案，落盘 + 加载前向兼容 / 迁移）、MEMORY_SCHEMA_VERSION（长期记忆，已落地 aiPartner_MemoryStore.py——按伴侣分桶持久化情感记忆 + 关系史 + 学到的用户事实 fact，原子落盘 / fail-safe / 前向迁移，输出喂 System Prompt 的 {情感记忆}/{关系史}；护栏已从预留升级为 set 键，删记录类型=BREAKING）。
  • 行为 / 策略版本（防溯源不了）：STATE_VERSION（状态机 / 同频调制）、SAFETY_RULES_VERSION（危机词库，危机命中即记入产出，供审计「当时用的哪版词库」）。
  • 契约 / 接口版本（防上下游不认）：OUTPUT_SCHEMA_VERSION（LLM 返回 JSON 契约，与文案版本解耦）、PLUGIN_CONTRACT_VERSION（互动插件契约，注册时校验，拒绝不兼容插件）、MODEL_CONFIG_VERSION（模型 / 调用配置，含 json 响应模式；每次请求携带 X-Yuan-Config-Version 头供遥测）。
  • 授权 / 文案版本（沿用既有）：POLICY_VERSION（授权说明，§16.1）、PROMPT_VERSION（System Prompt 文案 / 人格 / 红线文本，与输出契约解耦）。
  • 配置 / 资源版本（可溯源的预设资源）：TTS_VOICE_VERSION（声线模版，§13 已落地 aiPartner_VoiceTemplate.py；护栏双维度——tts_voice 按声线 ID 集合比增删，删=阻断 / 加=兼容；tts_voice_params 按参数内容 + 路由别名 TIMBRE_ALIASES 哈希比，变了=需复核）。
  • 发布版本：APP_VERSION（语义版），聚合回滚 / 崩溃上报关联 / 遥测。

聚合入口 aiPartner_Version.py：VERSION_REGISTRY 汇集上述所有常量（各常量仍定义在其子系统旁，沿用 POLICY_VERSION / PROMPT_VERSION 的范式，不重复定义），提供 all_versions()（喂遥测 / 崩溃上报）与 summary()（上线核对）。Orchestrator status() 暴露相关版本；chat() 回包带 prompt_version / output_schema_version / safety_rules_version。

版本纪律：改对应子系统必须同步升对应版本号；持久化数据（伴侣档案）加载时做前向兼容与迁移，损坏文件仍 fail-safe 不虚构。

17.1 版本升级护栏（让版本号长牙）

版本号铺满不等于安全——「升了版本」和「内容真的变了」之间靠人肉 review 会漏。新增 aiPartner_version_guard.py 把两者钉死，作为提交前 / CI 的阻断闸门：采集每个受约束子系统的「版本号 + 内容指纹」快照，首次运行写 aiPartner_version_manifest.json 基线（随代码提交）并比对。结论分三类——阻断（exit 1）：内容变了却没升版本，或升了版本但删了字段 / 词 / 契约项（破坏性，需迁移说明 + 复核）；兼容：升了版本只新增（加危机词、加输出字段）；复核（WARN）：无意义 bump，或升版本且文案 / 配置变了（请人工复核）。结构化项（输出契约字段、危机词库、档案字段白名单、插件契约字段、长期记忆记录类型、声线模版 ID 集合）按集合算增删（删项=BREAKING，例如删一个记忆类型 / 声线会直接拦下），不透明项（授权说明、Prompt 固定段、状态机信号面、模型调用配置默认值、声线参数 + 路由别名 TIMBRE_ALIASES）按内容哈希比对（声线参数 / 别名变了=需复核）。

用法与 CI：python aiPartner_version_guard.py（默认比对，有阻断则 exit 1）；--update-baseline（升级后重记基线再提交）；--strict（WARN 也失败）。test_aiPartner_version_guard.py 含真实变异用例，与全量套件一并跑绿。
